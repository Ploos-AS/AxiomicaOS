# M0.3 — Amiga boot bring-up

M0.3 separates qualification into two independent gates. Both must pass before the milestone may be released.

## Static gate

PASS requires:

- exactly 880 KiB ADF image
- valid Amiga boot signature
- valid boot-block checksum
- AXAM v1 container at byte 1024
- 32-byte big-endian AXAM header
- `load=0`, meaning relocatable/bootstrap-selected placement
- zero flags and reserved metadata
- payload size matching the AXAM header
- valid embedded payload checksum

Run:

    python3 tools/amiga/qualify-static.py build/m68k-amiga/axiomicaos-amiga.adf

The generator (`mkboot.py`), container checker (`checkboot.py`) and static qualifier all define `load=0` as the AXAM v1 contract. A fixed load address is not an M0.3 invariant.

## Runtime gate

Runtime PASS requires a controlled A500/68000 FS-UAE run that produces verifier-approved evidence showing the ordered AxiomicaOS runtime oracle sequence, including both kernel entry and halt.

The dedicated self-hosted runner must use a legally obtained ROM stored outside the repository, Actions artifacts, caches and images.

A host preflight PASS only establishes that the runner is ready. A static PASS only establishes image invariants. Neither may be reported as M0.3 runtime PASS.

## Release rule

M0.3 may be tagged/released only when:

1. the static gate passes for the exact qualification image;
2. the runtime gate passes for that image; and
3. the runtime evidence artifact is retained by the qualification workflow.
